# 工料机调量与临时删除迭代记录

## 已验证的能力

- 选中父定额后，`native-inspect` 一次读回工料机全表。实测带旁通水表井 4-29 读回 48 行，包含资源编码、规格、单位、现含量、数量、市场价、锁量及原含量。
- 本地开发版支持从工料机表修改单单位含量，并按父定额工程量读回计算后的数量。父定额由“定”变为“换”是正常结果。保留资源身份及单价核对，正常换算只允许目标行及其上级出现应有变化。遇到写入已接受但验证中断时，从原命令只读核对，避免重发。
- 本地开发版支持按分部、父定额全名、主材身份和原工程量临时删除预算树中的主材。成功以删除线及数量、合价归零为准。部分主材的临时删除未产生变化，现场通过含量归零退出计价，记录时区分这两种操作。
- 以上为本机工作区实测，发布标签 `v0.2.0b5` 与本地开发版有差异。该记录不代表新版本已发布。

## 临时删除仍待查明的问题

- 同一工程中，旧顶板 2-6 临时删除生效，旧钢筋 4-4、井盖 1-22 和垫层 2-1 在 CLI 触发后无变化。人工可执行临时删除。已知 CLI 找到了正确目标行，回执确认请求进入队列，后续快照没有删除线，原数量及合价保持原值。另一次同步触发试验也未生效。
- 现有回执缺少队列回调是否实际调用动作、动作处理了哪个选区的证据。下一轮在隔离样例中对照同一目标的人工成功与 CLI 失败，记录触发瞬间的焦点、当前单元格、选中行、动作启用状态和执行回调结果。
- 将已排队、已触发、有删除结果、无变化和结果待核分开记录。临时删除后原工程量会归零。后置校验按原目标身份、路径及删除线确认，同时验证其余预算行和上级合价。原调量或删除未决时，先核对原意图和快照。
- 从主材选区打开查询可能进到人材机查询。定位预算父项成功后，再查定额。工料机视图刷新后资源行号可能变化，写入前以完整父项、资源编码、单位和原含量确认。

## 调量提速方向

- 五项实际调量的原生检查、写入及读回区间合计约 16 秒。正常单项 CLI 命令的间隔在 9–10 秒左右。更长的现场用时还包含首次写入后对“定→换”的误判、恢复、视图定位和多次无效果的临时删除。单次新增定额并填量的原生流程约 23 秒，查库和插入应独立计时。
- 优先实现同一父定额的批量含量编辑。一次读取全表并提交修改清单，复用编译产物和原生运行环境。逐项核对原值并写入，结果明确后立即推进，最后整表核对含量、数量、价格和预算。遇到弹窗、视图变化或结果不明时停在该项，由原回执续接。
- 后续再将复用运行环境扩展到连续套项。验收时用相同的资源清单比较端到端耗时，并拆分编译、启动、定位、写入、刷新和读回。异常路径应验证不会重复写入。工料机材料换档与本次含量编辑是两套业务，单独验证实际资源编码替换。
